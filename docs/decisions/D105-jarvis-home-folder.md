# D105: Jarvis's knowledge lives in one home folder that grants no authority

[← Decision Index](INDEX.md)

**Date**: 2026-10-09

**Status**: Active

**Research**: the Jarvis plan attached to [VGS-1194](https://linear.app/vanillagreen/issue/VGS-1194)

**Refines**: [D070](D070-jarvis-action-policy.md), which stays the only source of permission, and [D079](D079-brains-wire-and-harness-adapters.md), whose harness program keeps its private working folder

**Decision**: One folder the user picks holds what Jarvis knows: `AGENTS.md`, the base skill package, the user's skills under `skills/own/`, `memory/` and `state/`. The base package is kendex's Jarvis package at the paths a kendex install writes: `.agents/skills/jarvis/`, the skills it requires and, in each harness folder the home manages, the agents it names. It has one writer per home: kendex where kendex's lock in the home names the Jarvis skill, else VGS, which copies the render it ships, `packaging/jarvis-home/`, but no path kendex's lock names and no file of the user's, lists the files it wrote in `.vgs-package.json`, and replaces or removes only those. The open removes `skills/base/`, VGS's earlier copy. A Jarvis skill at `.agents/skills/jarvis/` that is absent, partial, a link or holds a link refuses the home, and so does a render VGS ships that lacks a skill or an agent the package declares. Its text reaches every brain by one route, and the voice that only reads the brain's words aloud gets none. `Guidance.compose` adds `AGENTS.md` and an index of the skills to the shipped guidance, and each skill body is a `help` topic read through the router. A brain's harness program never runs in the home, so it loads none of the home's settings, hooks or MCP servers, and each vendor's own memory is off at launch. Home text carries the release label `home`: it taints no turn and goes to the conversation's recipients without a grant. The gate protects the whole home folder through `Denied`: a model's file tool, shell command or harness approval reaches no path in it but `state/`. One route the gate owns adds to the folder outside `state/`: the `fleet.request` tool hands one request a turn to the Jarvis session's mailbox by running `scripts/lane-mail` of the mailbox skill of the `vanillagreencom/kendex` package, installed at `.agents/skills/mailbox/scripts/lane-mail`, the one program of a home a brain's action starts, because kendex owns that mailbox's rows, lock and reader and a second writer in VGS would drift from them. The Jarvis session is not a brain. The shell starts and stops it only through the session command of the kendex Jarvis package in the home, `.agents/skills/jarvis/scripts/jarvis-session`, the second program of a home VGS starts: the package owns the session's record, its resume and its hand-over, and VGS ships no launcher of its own. The session that command starts is the user's own program: it loads the home's settings, hooks and servers, as `.claude/settings.json` in the home assumes, and runs outside the gate.

**Why**: A wire brain has no working folder, so only the instruction route gives every brain the same knowledge. Two writers of the base package in one home would leave two versions, and the brain could read one that `kendex refresh` did not fetch. A layout of VGS's own would leave the package's agents unable to find the Jarvis skill they load, so a home VGS makes holds the package where a kendex install puts it. A brain's program started in the home would load its hooks, extensions and MCP servers outside the gate, and each vendor loads a different part of a folder. The Jarvis session is already a trusted writer of the home, so the shell starting it gives no model a path it did not have, and a second launcher in VGS would drift from the package's record of which session is Jarvis.

**Rejected**: Each harness program with the home as its working folder, reading `AGENTS.md` and skills its own way. It reaches no wire brain, and the home's hooks and servers would act without the gate.

**Revisit when**: A vendor's program reads a folder's instructions without its settings, hooks and servers, home text gains a writer outside the user, VGS and the Jarvis session acting as the owner's delegate, or a brain needs home knowledge the instruction route cannot carry.
